# MC 量体三端交互原型

本仓库包含管理后台、裁缝端和客户端三个独立静态入口。

根目录 `index.html` 提供三端统一预览入口，GitHub Pages 通过 `.github/workflows/deploy-pages.yml` 自动部署静态文件。

## 访问入口

- 管理后台：`/measure_admin/`
- 裁缝端：`/tailor/`
- 客户端：`/client/`

## 服装版型、产品配置与师傅量身（2026-09-19）

后台“衣服版型管理” → “产品配置” → 师傅端“按产品量身”形成同源浏览器内的完整录入流程。

- 服装下维护多个版型及标准尺码，支持手动录入、XLSX / CSV / TSV 导入，提供与示例尺码表一致的 CSV 模板。
- 产品可不绑定服装版型，直接配置字段（例如毛衣单选 S、M、L）；需要预设尺码时选择服装、勾选版型后初始化字段；使用独立快照，后续修改产品不会改动版型库，版型库变化也不会覆盖已配置产品。
- 产品字段支持数字、文本、单选、多选；数字和版型默认值采用紧凑输入，备注使用长输入框。
- 单选、多选为产品通用字段，不再按版型配置默认值；支持逐行、逗号或顿号录入选项及实时预览，“特体”示例包含平肩、溜肩、凸肚、挺胸、驼背。
- 师傅端按员工性别读取已配置产品，版型平铺单选；字段默认折叠，同一时间展开一项，摘要显示默认值和本次结果。
- 数字字段支持版型加减与净体录入；通用选项采用平铺单选 / 多选，切换版型时保留。提交记录保存产品及版型快照，后台量体列表和 CSV 可核对。
- 当前产品配置未绑定订单；尚未配置任何产品时保留旧固定字段流程，配置后若无适用性别的产品则提示补充配置。此流程仅适用于本机原型模式，不扩展远程 API。

实现文件为 `measure_admin/catalog.js` 与 `tailor/products.js`，两者均纳入 Pages 静态发布清单。详细说明见 [管理后台](measure_admin/README.md) 和 [师傅端](tailor/README.md)。

## 本地运行

在仓库根目录执行：

```bash
python3 -m http.server 8767
```

然后访问：

```text
http://localhost:8767/measure_admin/
http://localhost:8767/tailor/
http://localhost:8767/client/
```

各端当前均为静态交互原型，不连接生产数据库。详细交互和数据规则见各目录内的 README。

## 原型维护范围

- 后续需求默认只修改本仓库 `demo_measure_git/` 内的静态交互原型及其 README 文档。
- 不同步修改上级项目中的正式源码、Python 服务端、SQLite 数据库或部署配置。
- 只有在需求中明确写明“修改源码”“接入服务端”“修改数据库”等要求时，才调整 `demo_measure_git/` 以外的正式实现。
- 管理后台原型功能以 `measure_admin/index.html`、`measure_admin/app.js`、`measure_admin/styles.css` 和 `measure_admin/README.md` 为准。

## 批量导入更新流程状态（2026-10-08）

管理后台支持正向订单和退换售后状态导入，提供带现有记录的 CSV 模板，接收 CSV / TSV / XLSX 文件。正向按订单号＋员工编号、售后按售后编号匹配，校验预览后统一保存；保留顺序推进、送厂日期必填与收货校验规则。员工端同步展示更新结果。每次最多 10,000 行，预览分页显示；详细操作见 [管理后台说明](measure_admin/README.md)。

## 预计交付日期（2026-10-08）

- 正向订单与售后退换保留现有流程节点；进入“已下单到工厂”时，通过日期选择框必填预计交付日期，取消不会推进状态。
- 售后单笔和批量下单均支持；批量下单使用同一日期，仍须先收齐服装或关闭不需送厂的申请。
- 客户端订单卡、售后列表与售后详情显示各自的预计交付日期，后续交付节点保留该日期；历史记录没有日期时不补造数据。
- 日期沿用原型共享存储，正向按员工与订单保存，售后按申请保存，并写入下单状态记录。

## 订单执行与售后（更新于 2026-09-16）

### 正向订单进度

服装确认 → 预约量身 → 完成量身 → 已下单到工厂 → 工厂交付，待派送 → 已交付。

- 按员工与订单匹配进度，员工签字确认、有效预约和裁缝提交量体记录驱动前段进度。
- 管理后台“订单管理 → 变更订单进度”可按员工依次确认全部六个节点，也可勾选同进度员工批量更新；禁止跳步，进入工厂下单时必填预计交付日期。
- 手动确认仅更新进度，不生成签名、预约或量体档案；操作记录包含状态、时间、操作人及下单日期。
- 员工端订单卡展示完整节点、已完成阶段、下一步、预计交付日期与后台更新记录。同源同浏览器页面通过共享存储同步，返回员工端或切回页面时也会刷新。

### 员工售后申请与详情

提交售后 → 门市收货 → 已下单到工厂 → 工厂交付，待派送 → 完成派送。

- 员工从订单卡“提交售后”，选择退换服装、申请数量，填写逐项修改要求和补充说明。每次申请独立保存，可多次申请。
- 服装优先使用员工已确认明细；未确认时使用所属订单按性别配置的服装及默认数量。申请数量必须为正整数且不超过对应数量，每项修改要求必填。
- “我的订单”先展示申请列表：订单号、申请编号、提交时间、当前进度节点及简化进度条。
- 点击单条申请进入详情，查看完整进度、退换明细、申请备注及最近一次门市签收信息；返回时保留列表滚动位置。
- 详情逐项区分“申请数量”和“签收数量”，签收数量为多次实际签收的累计值。尚未签收显示“待签收”，旧记录缺少实收数据时显示“未记录”，不以申请数量代替实收数量。
- 员工详情不展示处理日志；已关闭服装显示关闭状态和原因，整单全部关闭时显示“已关闭”。

### 门市分次签收与单项关闭

- 主账号可操作售后；子账号需在“子账号管理”中勾选“售后管理”权限。
- 后台“售后管理 → 查看详情 / 处理”展示申请数量、累计签收数量、修改要求及每项服装处理状态。
- 支持多次新增签收，填写的是本次实收数量，未带来的填 0；数量必须为非负整数，每次合计至少 1 件，累计不得超过申请数量。
- 每次签收独立保留时间、各服装数量、备注和操作账号。操作人及账号 ID 自动取当前登录身份，无需手填。
- 后台状态记录包含“时间 / 状态或操作 / 操作人”；旧日志缺失身份时显示“未记录”。员工端同步累计签收及最近签收信息。
- “提交售后”“门市收货”阶段可关闭单项服装申请，关闭原因必填。保留原申请、已签收数量、关闭原因、时间及操作人；关闭项目不计入待送厂数量。
- 仍需处理的服装全部收齐后，才能进入“已下单到工厂”；工厂与派送阶段按顺序推进。批量操作要求全部所选申请可进入同一下一阶段。
- 全部服装关闭后整单为“已关闭”，不再签收或推进；“完成派送”同样为终态。送厂后不可追加签收或关闭服装。

示例：员工申请外套 2 件、西裤 1 件、毛衣 1 件。今天签收外套 1 件，明天签收外套 1 件和西裤 1 件；毛衣现场换货，关闭毛衣申请并备注“现场退换”。此时外套累计签收 2 件、西裤 1 件，毛衣不计入待送厂数量，剩余服装可进入工厂流程。

### 售后明细导出

后台按员工 / 申请编号、单位、提交日期、状态筛选，导出全部筛选结果（不限当前页），每个服装项目一行。包含申请数量、累计签收数量、修改要求、备注、申请进度、最近签收信息、服装状态、关闭原因、关闭操作人及待送厂数量；关闭项目的待送厂数量为 0。

详细说明：[员工端](client/README.md)、[管理后台](measure_admin/README.md)。

## 预约管理

时段绑定订单，包含地址、日期、起止时间、容量、是否支持超额及开放状态。员工仅查看当前订单的可预约时段；已有预约时先提示地址与时间，可查看并取消。后台支持批量导出预约明细。

## 裁缝端预约明细（2026-09-16）

- 本机原型模式登录后，可随时打开预约明细，默认查看今天，支持按日期、订单、时段及量身状态筛选，并统计预约、待量身和已量身人次。
- 人员名单仅展示员工编号与姓名，多人以“；”分隔，例如 `EMP001 陳嘉儀；EMP002 李國輝`。
- 同订单、同员工在预约当天（北京时间）且登记预约后提交量体记录，才计为本次已量身；取消预约不显示。
- 名单为只读弹窗，关闭后保留当前步骤及填写内容，不改变员工查询、量体提交和下一笔流程。详细规则见 `tailor/README.md`。

## 数据与兼容

- `shared/workflow.js` 统一初始化三端演示数据、迁移旧售后状态并计算进度；直接首次打开任一端即可初始化数据。
- 三端共享同源 `localStorage`，客户端和后台监听其他标签页的数据变动。仅为当前浏览器的原型联动。
- 旧版“已登记 / 已处理 / 已完成”映射为“提交售后 / 门市收货 / 完成派送”；更早版本按其旧语义迁移。旧记录的内容和状态历史保留，不伪造签收人或签收时间。
- 旧的单次签收在新增签收时作为首批记录保留，累计时不会重复计算。
- 发布工作流包含共享脚本，仅发布静态运行文件。
