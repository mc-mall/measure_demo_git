# MC 量体管理后台原型

本目录是从现有 `measure-admin` 初始化的独立静态管理后台原型。

当前保留以下交互：

- 原型登录与退出
- 总览统计
- 裁缝师、订单、员工的新增、编辑与删除
- 创建或编辑订单时，按男士、女士配置客户端可选服装类型
- 为每个服装类型配置默认数量，以及员工是否可以更改数量
- 可选配置同一性别下多个服装类型的组合数量限制，支持“刚好”和“不多于”条件
- 从具体订单进入签字明细，按员工查看客户端确认的各服装数量与验证状态，支持搜索、分页、导出，并撤销已完成的签字验证
- 员工筛选、分页、批量导入和量体档案模板导出
- 员工量体档案、版本修改与移除
- 男士、女士量体记录筛选、分页与 CSV 导出
- 量体版本对比分析向导与结果导出
- 售后管理：查看员工提交的退换服装、数量、逐项修改要求与补充说明
- 门市现场逐项填写实际签收数量后签收，记录签收人、时间、实收明细和备注
- 售后列表支持筛选、分页及导出全部筛选明细；工厂与派送节点支持顺序批量推进
- 订单管理提供“执行进度”，按员工推进工厂下单、工厂交付与最终交付
- 预约管理：新增、编辑和删除无预约记录的服务时段，并绑定对应订单，配置预约地址、服务日期、起止时间、可预约最大值、是否支持超额预约及开放状态
- 预约列表实时统计当前预约人次与超额人数，并可查看每个时段的预约员工明细；已有预约的时段只能暂停，不能直接删除

## 子賬號角色權限（2026-10-28）

- “系統配置 → 角色權限管理”按“歸屬 / 頁面 / 接口”維護角色，可全選、清空及逐級勾選，角色支持啟用與停用。
- “子賬號管理”改為多選角色；保存後合併繼承多個角色的權限，列表展示角色、狀態和綁定數量。
- 只要仍有一個啟用角色，子賬號即可登入；所選角色全部停用時會阻止登入。刪除仍有子賬號綁定的角色前，需先改綁其他角色。
- 舊版本只保存 `permissions` 的子賬號仍可登入，系統會保留舊字段作為遷移期間的回退權限。

## 衣服版型管理与产品配置（2026-09-19）

主账号从“系统配置”进入“衣服版型管理”及“产品配置”。数据与三端原型共用浏览器 `localStorage`，不连接生产数据库。

### 维护服装版型

1. 创建服装名称，例如“西装外套”，添加 46A、46B、46C 等版型。
2. 逐行维护胸围、袖长等字段；每个版型一列，另设净体默认值、最小值、最大值和备注。空白为未设置，0 为有效数值。
3. 可下载 CSV 模板用 Excel 编辑，或导入 XLSX、CSV、TSV。第一行为服装名称，第二行为“字段、各版型名称、净体、最小值、最大值、备注”，第三行起为尺码数据；XLSX 读取第一张工作表，不支持旧式 XLS。
4. 导入先校验数字、重复名称、上下限及版型默认值范围；失败不写入，成功后可核对修改再保存。替换当前草稿会提示确认。
5. 已绑定产品的服装不能直接删除；同名服装不能重复创建。

### 配置产品

1. 设置产品名称和性别。服装来源和版型均为选填，无预设尺码时可直接添加字段，例如“毛衣 → 尺码 → 单选 S、M、L”。需要预设尺码时再选择服装并勾选适用版型；支持全选、清空和已选数量提示。解除绑定会保留字段及通用选项，只清除版型选择和相关默认值。
2. 点击“初始化产品字段”，复制字段、所选版型的默认值、净体默认值、范围和备注；重新初始化会确认后替换当前字段及手动修改。
3. 可修改字段名称、类型、排序、必填、填写提示，或添加 / 删除字段。每个字段可勾选“是否警告”（默认关闭），师傅展开操作该字段时持续显示红字“注意放量，及时调整尺码版给客人重试”；仅提示，不阻止录入或提交。名称、类型和数值框紧凑排列，备注保持长输入框；多个版型默认值等宽排列、自动换行。
4. 产品保存独立配置快照；修改产品不影响版型库，版型库更新不自动覆盖产品。同名同性别产品不可重复创建。

### 通用单选与多选

- 单选 / 多选只配置一组产品通用选项，不再显示或保存各版型默认值，师傅端初始不预选。
- 独立选项编辑区支持每行一项，以及逗号、中文逗号或顿号分隔，右侧实时预览。空选项组和重复选项不能保存。
- “填入特体示例”提供“平肩、溜肩、凸肚、挺胸、驼背”，替换已有选项前会确认。单选只能选择一项，多选允许选择多项，均可设置必填。
- 旧的按版型配置的选项默认值立即停用，保存产品时移除；历史已提交量身快照保留。

### 师傅端联动与记录

- 当前按员工性别读取全部对应产品，尚未将产品绑定到具体订单；客户端的订单服装数量配置沿用原有逻辑。
- 师傅先选版型，再填版型加减量或净体尺寸；通用选项可提前填写，切换版型仍保留。
- 量体列表及 CSV 的“产品版型量身明细”保存并展示所选版型、默认值、加减量、成衣 / 净体结果和通用选项。提交记录另存产品字段快照，后续配置调整不影响历史。
- 新的动态字段保存在 `产品ID.字段ID` 键下；旧档案编辑器仍用于原固定字段，保存时保留动态字段。旧固定字段版本分析未扩展为动态产品分析。

## 预约管理流程

1. 管理员在“预约管理”新增服务时段，先选择对应订单，再填写地址、日期、开始与结束时间、最大预约人数。
2. 管理员可选择是否支持超额预约，并可暂停或重新开放时段。
3. 员工从订单卡进入“量体预约”，客户端只读取该订单绑定的开放时段，并展示服务地址、时间、最大值和当前预约人数。
4. 员工登记或取消后，管理后台的当前人数和预约员工明细同步更新。
5. 不支持超额的时段满额后停止登记；支持超额的时段继续登记，并在后台标记超额人数。

## 售后管理（更新于 2026-09-16）

员工提交售后 → 门市收货 → 已下单到工厂 → 工厂交付，待派送 → 完成派送。

### 入口与权限

- 员工在客户端提交独立售后申请，门市不再代为新建；多次申请分别处理。
- 主账号可使用售后管理；子账号在“子账号管理”勾选“售后管理”权限后，可查看详情、分次签收、关闭服装、推进状态和导出。
- 操作人及账号 ID 自动取当前登录身份，状态记录中显示具体账号；

### 售后详情

- 基本信息：申请编号、员工、订单、当前状态、提交时间和最后更新时间。
- 服装明细：服装名称、申请数量、累计签收数量、修改要求和服装处理状态；已关闭项目显示原因、操作人及时间。
- 申请补充说明。
- 状态记录表：时间、状态 / 操作、操作人，记录签收、关闭服装和后续状态推进。
- 签收记录：按批次展示每次签收时间、实收服装及数量、备注、操作账号。

### 多次签收

1. 在“提交售后”或“门市收货”阶段打开“新增签收”，查看每项服装的申请、已收和待收数量。
2. 填写本次实收数，未带来的填 0。数量必须为非负整数，不能超过该项待收数量；本次合计至少签收 1 件。
3. 核对确认后新增一个签收批次，累计数量更新，原申请数量保持不变。
4. 可在后续到店时继续签收剩余服装；每批独立保留数量、时间、备注和操作账号。已收齐或已关闭的服装不再提供签收输入。
5. 旧的单次签收在首次新增批次时保留为第一批，不覆盖历史或重复累计。

例如申请外套 2 件，今天收到 1 件，显示“申请 2 / 累计签收 1”；明天再收到 1 件，新增第二批，累计变为 2 件。

### 单项关闭与送厂规则

- 送厂前可点击“关闭此服装申请”，必须填写原因，例如“现场退换”。
- 关闭只作用于该服装项目，保留申请数量和实际签收事实，并记录关闭原因、时间及操作账号；其他服装继续处理。
- 关闭项目不再签收，也不计入待送厂数量。例如毛衣现场有货可换，关闭毛衣并备注“现场退换”，外套签收后仍可送厂修改。
- 所有未关闭服装必须收齐，才能下单到工厂。批量送厂同样检查此条件。
- 全部服装关闭后整单显示“已关闭”，不再签收或推进；关闭项目不会被当作完成派送。
- 送厂后不可追加签收或关闭服装，工厂交付、完成派送按顺序推进。批量操作仅处理可进入同一下一阶段的记录。
- “完成派送”为终态；再次售后由员工提交新申请。

### 明细导出

“导出筛选明细”覆盖当前筛选条件下的全部记录，不限当前页，每个服装项目一行：

- 申请编号、订单、员工编号、姓名、性别、单位、提交时间。
- 服装、申请数量、累计签收数量、修改要求、申请备注、整单进度。
- 最近签收人、最近签收时间及备注；逐次签收明细在详情的签收记录中查看。
- 服装状态、关闭原因、关闭操作人、待送厂数量。关闭项目的待送厂数量为 0；未关闭项目取累计实收量，此字段不表示已经下单到工厂。

## 正向订单进度

订单管理 → 执行进度：按员工展示服装确认、预约量身、完成量身、已下单到工厂、工厂交付待派送、已交付。前三步读取员工签字、预约及裁缝量体记录；完成量身后由后台逐步确认后三步，并保留操作记录。

## 本地运行

在仓库根目录启动任意静态服务器。例如：

```bash
python3 -m http.server 8767
```

然后访问：

```text
http://localhost:8767/measure_admin/
```

## 数据说明

- 原型数据保存在当前浏览器的 `localStorage` 中，不连接生产数据库。
- 主账号使用任意非空演示账号密码；已建立的子账号须使用指定密码，校验账号状态和密码哈希。原型不保存输入的明文密码。
- 裁缝师密码不以明文写入源码、页面或浏览器存储；列表仅展示是否已设置。
- 裁缝端与本后台在同一站点下共享订单、员工及量体记录数据。
- 客户端与本后台共享员工签字验证状态；客户端签字后转为已验证，后台撤销后恢复未验证。
- 客户端与本后台共享预约时段及预约记录；该联动只发生在同一浏览器、同一站点的原型数据中。
- 清理站点数据会重置原型数据。


## 正向订单进度操作（2026-10-08）

在“订单管理 → 变更订单进度”查看每位员工的当前阶段。主账号可逐笔确认下一阶段，或勾选同阶段员工并选择下一阶段批量更新。六个节点按原顺序推进，不支持跳步或回退；“已下单到工厂”需填写预计交付日期，批量时共用该日期。取消不保存。

员工签字、预约、量身仍会自动更新进度；后台手动确认只维护进度，不代建业务凭证。列表保留状态、操作时间、操作人和预计交付日期；员工端订单卡同步显示进度和更新记录。本原型同步范围为同源、同浏览器共享存储。


## 导入更新正向与退换状态（2026-10-08）

- 正向入口：“订单管理 → 变更订单进度 → 导入更新状态”。模板包含当前订单全部员工，以“订单号＋员工编号”匹配，不能更新其他订单。
- 退换入口：“售后管理 → 导入更新状态”。模板包含当前筛选下的全部售后记录（不限当前分页），以“售后编号”匹配；文件带有订单号或员工编号时也会交叉核验。
- 下载 CSV 模板，填写“目标状态”和送厂时必填的“预计交付日期”，上传 CSV、TSV 或 XLSX 首张工作表。支持简繁体字段名与状态，编号应保存为文本以保留前导零；日期推荐 YYYY-MM-DD，也支持标准 Excel 1900 日期系统的日期单元格。1904 日期系统须转换或另存 CSV。
- 每次最多 10,000 行、10 MB，校验预览每页 100 行。目标状态空白行、已经达到同一目标状态的记录略过；重复记录、无效编号/日期、跳步、回退等错误阻止整批保存。模板中的姓名、目前状态仅供参考。
- 状态仅允许推进下一节点；售后门市收货须已有实际签收凭证，送厂须收齐或关闭无需处理的服装。导入不会生成签名、预约、量体或收货凭证。
- 确认前重新核验最新数据，预览变化时须再次核对。成功后统一保存状态、预计交付日期、操作人、时间和导入来源，员工端同步可查。取消预览不会写入数据。

实现：`status-import.js`；测试：`node --test tests/*.test.cjs`。
